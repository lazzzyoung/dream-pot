# CLAUDE.md

부품상(Parts Shop) 프로토타입 작업 지침.

## 이 프로젝트가 뭔지

저축액을 코인으로 바꿔 목표 물건의 부품을 하나씩 사고, 반투명 설계도가
실물로 채워지는 걸 보는 앱. 상세 요구사항은 `PRD.md`에 있다. **작업 시작 전 반드시 읽을 것.**

핵심은 재무 정확도가 아니라 **매달 열어보고 싶은 기분**이다.
계산이 한 달 어긋나는 건 괜찮고, 구매 연출이 밋밋한 건 안 괜찮다.

## 기술 스택 — 고정

- **의존성 없는 정적 HTML/CSS/JS.** 빌드 스텝 없음, npm 없음, 프레임워크 없음
- ES 모듈로 파일 분리 (`<script type="module">`)
- 저장소는 localStorage 하나
- 차량 도면은 인라인 SVG. 이미지 파일 아님

이 제약은 협상 대상이 아니다. 사용자의 기존 재무 앱(`~/Desktop/재태크/finance-app/`)이
같은 방식이라, 나중에 탭 하나로 합칠 수 있어야 한다.
React나 Vite를 쓰고 싶어지면 그 충동을 무시할 것.

## 파일 구조

```
parts-shop/
  index.html
  css/
    tokens.css      디자인 토큰. 색·타입·간격 변수만
    app.css         레이아웃과 컴포넌트
    motion.css      애니메이션. reduced-motion 처리 포함
  js/
    main.js         진입점, 라우팅(화면 전환)
    store.js        상태 읽기/쓰기, localStorage, 마이그레이션
    catalog.js      검색 카탈로그 데이터
    parts.js        부품 세트 정의, 가격 계산
    screens/
      search.js     목표 검색
      confirm.js    등록 확인 시트
      main.js       메인 화면 조립
    ui/
      blueprint.js  SVG 도면 렌더링 + 부품 상태 반영
      shop.js       부품 카드 그리드
      keeper.js     상점 주인 캐릭터와 대사
      deposit.js    저축 인증 카드
  svg/
    model3.js       모델3 SVG를 문자열로 export
```

## 코딩 규칙

- **상태 변경은 `store.js`를 통해서만.** 다른 모듈이 localStorage를 직접 만지지 않는다
- store는 변경 시 이벤트를 발행하고, UI 모듈이 구독해서 다시 그린다.
  전역 재렌더링으로 시작하고, 느려지면 그때 최적화한다
- 순수 계산(부품 가격, 완성 예상일, 인증 가능 여부)은 `parts.js`에 모으고
  DOM을 모른 채로 유지한다. 테스트하기 쉬운 상태를 지킬 것
- 금액은 항상 정수 원 단위. 부동소수점 누적 금지
- 한국어 UI. 코드 주석과 변수명은 영어

## 검증

이 프로젝트엔 테스트 러너가 없다. 대신 매 변경 후 브라우저에서 직접 확인한다.

체크 순서:
1. localStorage 비우고 새로고침 → 검색 화면이 뜨는가
2. 테슬라 검색 → 등록 → 메인 진입
3. 인증 → 코인 증가
4. 섀시 구매 → 다른 부품 잠금 해제
5. 휠 2개 구매 → 도면에 정확히 2개만 실물
6. 새로고침 → 상태 유지
7. 375px 폭으로 줄여도 안 깨지는가
8. OS 설정에서 모션 줄이기 켜고 → 애니메이션 대신 즉시 전환되는가

**동작 확인 없이 "완료"라고 말하지 않는다.** 스크린샷을 찍을 수 있으면 찍어서 확인할 것.
