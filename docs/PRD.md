# PRD — 부품상 (Parts Shop)

저축을 부품 구매로 바꿔서, 갖고 싶은 물건을 한 조각씩 조립해 나가는 프로토타입.

---

## 1. 문제

목표 금액이 큰 저축(수천만 원)은 진행률 막대 하나로는 동기부여가 안 된다.
"3,000만 원 중 240만 원 모음 (8%)"은 숫자일 뿐 아무 감정도 만들지 않는다.

반면 "앞바퀴 왼쪽을 샀다"는 소유의 감각을 만든다. 다음에 살 것이 명확하고,
그것이 눈앞의 도면에 실제로 채워진다.

## 2. 해결책 한 줄

저축액을 코인으로 바꾸고, 그 코인으로 목표 물건의 부품을 하나씩 사서
반투명한 설계도를 실물로 채워 나가는 앱.

## 3. 이번 프로토타입의 범위

**한 명의 사용자, 한 개의 목표, 로컬 저장.**
로그인·서버·동기화 없음. 브라우저 새로고침해도 상태가 유지되면 성공.

### 만드는 것
- 목표 검색 → 선택 → 등록 플로우
- 반투명 차량 도면 + 부품별 채우기
- 부품 상점 (캐릭터 + 카드 목록)
- 저축 인증 → 코인 전환
- 부품 구매 → 획득 연출 → 도면 반영
- 진행 현황 요약

### 안 만드는 것 (YAGNI)
- 회원가입, 계정, 서버, 멀티 디바이스
- 실제 은행 연동 (인증은 사용자가 직접 누르는 버튼)
- 목표 2개 이상 동시 관리
- 부품 판매/환불, 코인 소비 취소
- 푸시 알림, 이메일
- 소셜 기능, 랭킹, 친구

## 4. 사용자

29세 직장인. 월 소득 300만 원대 초반(예시 수치), 저축 여력은 빠듯하다.
기존에 스프레드시트형 재무 시뮬레이터를 쓰고 있지만 재미가 없어서 자주 안 연다.
이 앱의 목표는 **정확한 재무 계산이 아니라 매달 열어보고 싶게 만드는 것**이다.

## 5. 핵심 플로우

```
[0] 최초 진입 — 목표 없음
      ↓
[1] "저축해서 사고 싶은 것" 검색창
      ↓  "테슬라" 입력
[2] 검색 결과 카드 목록 → 테슬라 모델3 클릭
      ↓
[3] 예상 비용 확인 시트
      "테슬라 모델3 스탠다드 RWD — 약 4,699만 원
       이 금액으로 목표를 등록할까요?"
      [금액 직접 수정 가능] [월 납입액 입력] [등록하기]
      ↓
[4] 메인 화면 (이후 앱을 열면 항상 여기)
      상단: 반투명 도면 상태의 모델3
      중단: 코인 잔액 + 이번 달 인증 카드
      하단: 부품 상점 — 캐릭터 + 부품 카드 목록
      ↓
[5] 저축 인증 → 코인 지급 애니메이션
      ↓
[6] 부품 카드 구매 → 획득 연출 → 도면에 해당 부품만 실물로 전환
      ↓
      반복. 모든 부품 구매 시 완성 연출.
```

## 6. 화면별 요구사항

### 6.1 목표 검색 (`/` 또는 최초 진입)

- 중앙 검색창 하나. 플레이스홀더: `저축해서 사고 싶은 것`
- 입력 시 로컬 카탈로그에서 실시간 필터링
- 카탈로그는 하드코딩 JSON. 프로토타입에선 아래만 있으면 충분:

| 항목 | 기본가 | 부품 세트 | 상태 |
|---|---|---|---|
| 테슬라 모델3 스탠다드 RWD (신차) | 46,990,000 | `model3` | 완성 |
| 테슬라 모델3 롱레인지 (신차) | 59,990,000 | `model3` | 완성 |
| 테슬라 모델3 (중고, 2022년식) | 30,300,000 | `model3` | 완성 |
| 테슬라 모델Y 프리미엄 RWD | 49,990,000 | `model3` | 완성 |

- 검색어가 카탈로그에 없으면: "직접 등록하기" 옵션 노출 (이름 + 금액 입력)
  → 이 경우 부품 세트는 `model3`를 그대로 쓴다 (프로토타입 한정, 나중에 확장)
- **가격은 하드코딩된 참고값**임을 카드에 작게 명시. 실시간 시세 조회 아님.

### 6.2 등록 확인 시트

- 선택한 항목명, 이미지(또는 실루엣), 예상 금액 표시
- 금액은 수정 가능 (보조금·중고 시세 반영용)
- 월 납입액 입력 (필수). 기본값 500,000
- 시작일 입력. 기본값 오늘
- 등록 시 계산해서 보여줄 것: **"이 속도면 N년 M개월 뒤 완성"**
- [등록하기] 누르면 목표 생성 후 메인으로

### 6.3 메인 — 도면 영역 (상단)

- 목표 물건의 측면 SVG. 부품별로 `<g id="part-xxx">` 분리
- **미소유 부품**: 얇은 선만, 낮은 투명도, 점선 느낌 (설계도)
- **소유 부품**: 불투명 실물 색상
- 수량이 있는 부품은 개별 추적. 예: 휠 4개 중 2개 소유 → 해당 위치 2개만 실물
  - 휠은 앞좌/앞우/�좌/뒤우 순서로 채워짐 (측면도이므로 앞·뒤 2개만 보이면 됨 — 보이는 것부터 채운다)
- 우상단에 완성률 % 와 `소유 부품 수 / 전체 부품 수`

### 6.4 메인 — 코인 & 인증 (중단)

- 코인 잔액 크게 표시. **1 코인 = 1,000원** 고정 환산
- 인증 카드:
  - 다음 인증 가능일이 지나지 않았으면: 남은 일수 표시, 버튼 비활성
  - 인증 가능하면: `이번 달 500,000원 저축했어요` + [인증하기] 버튼
  - 인증 시 월 납입액 ÷ 1,000 = 500 코인 지급
- 인증 주기는 시작일의 일(day)을 기준으로 매월. 밀린 달이 여러 번이면 각각 인증
- **금액 수정 인증**: 인증 카드에서 이번 달 금액을 다르게 입력 가능 (보너스 받은 달 등)
- 인증 기록은 목록으로 보관 (날짜, 금액, 지급 코인)

### 6.5 메인 — 부품 상점 (하단)

- 상점 주인 캐릭터가 좌측에 상주. 상태별 대사 표시:
  - 코인 부족: 살 수 있는 게 없을 때
  - 구매 가능한 부품 있음
  - 방금 구매 직후
  - 전부 구매 완료
- 부품 카드 그리드. 각 카드에 표시할 것:
  - 부품명, 아이콘/썸네일
  - 가격 (코인), 원화 환산 병기
  - 수량 있는 부품은 `2/4` 형태로 소유 개수
  - 상태별 스타일: 구매 가능 / 코인 부족(비활성) / 완전 소유(마감 처리)
- 정렬: 구매 가능한 것 우선, 그다음 가격 낮은 순
- 카드 클릭 → 구매 확인 → 구매 실행

### 6.6 구매 연출

순서대로:
1. 카드가 살짝 들리며 도장/스탬프 효과
2. 코인 잔액이 카운트다운으로 감소
3. 카드가 상단 도면의 해당 부품 위치로 이동
4. 도면의 그 부품이 선 → 실물로 전환 (stroke draw-on 후 fill 페이드인)
5. 부품명 토스트: `앞바퀴를 손에 넣었습니다`

- 전체 1.2초 내외. 건너뛰기 가능 (아무데나 클릭)
- `prefers-reduced-motion` 존중 — 모션 대신 즉시 상태 전환

### 6.7 완성

- 마지막 부품 구매 시 특별 연출: 도면 전체가 실물로, 라이트 점등
- 완성 화면: 시작일 ~ 완성일, 총 저축액, 걸린 개월 수
- [새 목표 시작하기] 버튼

## 7. 부품 세트 정의 (`model3`)

가격은 **목표 금액에 대한 비중(%)**으로 정의한다. 목표 금액이 바뀌어도 자동으로 재계산된다.
비중 합계는 정확히 100이어야 한다.

| id | 이름 | 수량 | 비중(%) |
|---|---|---|---|
| `chassis` | 섀시 프레임 | 1 | 10 |
| `battery` | 배터리팩 | 1 | 24 |
| `motor` | 구동 모터 | 1 | 9 |
| `paint` | 도색 · 마감 | 1 | 12 |
| `door` | 도어 | 4 | 8 |
| `wheel` | 휠 · 타이어 | 4 | 6 |
| `suspension` | 서스펜션 | 4 | 6 |
| `seat` | 시트 | 5 | 6 |
| `sensor` | 오토파일럿 센서 | 1 | 4 |
| `hood` | 후드 · 트렁크 | 2 | 4 |
| `glass` | 윈드실드 · 사이드 글라스 | 1 | 3 |
| `lamp` | 헤드램프 · 테일램프 | 2 | 3 |
| `dash` | 대시보드 · 스티어링 | 1 | 3 |
| `display` | 센터 디스플레이 | 1 | 2 |

- 수량이 여러 개인 부품의 **개당 가격 = 목표금액 × 비중 ÷ 수량**
- 코인 환산 후 반올림. 반올림 오차로 총합이 목표금액과 어긋나도 무방 (프로토타입)
- 섀시는 **첫 구매 강제**: 다른 부품은 섀시 소유 전까지 잠금. 상점 주인이 이유를 말해준다.
  (조립 순서의 논리를 만들고, 초반 선택 피로를 줄이는 장치)

## 8. 데이터 모델

localStorage 키 하나에 전부. 키: `parts-shop:v1`

```json
{
  "version": 1,
  "goal": {
    "id": "model3-standard",
    "name": "테슬라 모델3 스탠다드 RWD",
    "totalPrice": 46990000,
    "partSetId": "model3",
    "monthlyDeposit": 500000,
    "startDate": "2026-09-01",
    "createdAt": "2026-08-27T10:00:00.000Z"
  },
  "coins": 500,
  "owned": {
    "chassis": 1,
    "wheel": 2
  },
  "deposits": [
    { "date": "2026-09-01", "amount": 500000, "coins": 500 }
  ],
  "completedAt": null
}
```

- `owned`는 부품 id → 소유 개수. 없으면 0
- `goal`이 `null`이면 검색 화면으로 진입
- 스키마 변경 시 `version` 올리고 마이그레이션 함수 추가

## 9. 계산 규칙

- **1 코인 = 1,000원**
- 부품 개당 가격(원) = `round(totalPrice × weight / 100 / count)`
- 부품 개당 가격(코인) = `round(원 / 1000)`
- 완성 예상 시점 = `ceil(totalPrice / monthlyDeposit)` 개월
- **이자·투자수익 계산은 하지 않는다.** 기존 재무 시뮬레이터의 역할이고,
  여기서 복리를 넣으면 화면만 복잡해진다.

## 10. 성공 기준

프로토타입이 성공했다고 말할 수 있는 조건:

1. 검색 → 등록 → 인증 → 구매 → 도면 반영까지 끊김 없이 동작
2. 새로고침 후에도 상태 유지
3. 휠을 2개만 샀을 때 도면에 정확히 2개만 실물로 보임
4. 구매 연출을 보고 "한 번 더 사고 싶다"는 기분이 듦
5. 모바일 화면(375px)에서 레이아웃이 깨지지 않음

## 11. 나중에 (이번엔 안 함)

- 기존 `finance-app`의 `state.json` 연동 — 월 납입액을 자동으로 읽어오기
- 목표 여러 개 (테슬라 + 전세보증금 동시 진행)
- 부품 세트 확장 (맥북, 여행, 카메라 등)
- 실제 시세 조회
- 상점 주인 캐릭터의 대사 다양화, 관계 시스템
